The heading is the answer
The milestone box is titled with the count that moved, not with a label. A planner who reads only that line and the first row has the month.
Each row
Name and code, the finish in each update, the slip in working days as number and bar (exploration 01, option B, same fixed scale as the grid), and Trace. The whole row opens the trace; Trace is there so that is discoverable.
Order
Later first, by size; then earlier, by size. An early move is good news and should not sit above a late one of the same size.
The rail
Three ways into other screens. Each line of "What changed" opens the changes view with that filter. Counts overlap (an activity can move and change duration), so there is no total; the line under the list gives the scale.

For Usman
1. Which milestones lead. (a) Every milestone in the schedule. (b) Only those the planner marks, remembered per project. (c) Every milestone, with finish milestones and those with a constraint date listed first, since contract dates are usually constrained. Drawn here as (a), cut to the 20 largest moves.
2. Which dates the summary uses. The dates stored in each file, or Slip's own recalculated dates. The spec says the file's dates are the source of truth until the planner makes an edit. Drawn that way; it means the summary can disagree with a trace, which uses recalculated dates.
3. Early moves. Listed after all late moves, as drawn, or mixed in by size.
4. A milestone that was added, removed or completed this month. Not drawn. It did not "move", but a planner would expect to see it here.
5. The copy. Every sentence in quotation marks is a first draft.
Not drawn
The navigation bar itself, which appears here for the first time and belongs to every later screen. The agent panel. What "See them" opens for the critical path.
