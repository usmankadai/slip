Import: three low-fidelity layouts

Hierarchy only: boxes and labels, no identity. The numbered tags show the order the eye should take. A heavy border marks what leads.

The planner's question: "Did my files load, and can I trust what loaded?"
Most prominent: two slots, A and B, each with project name, data date and activity count as soon as they are known.
Must not: hide warnings behind a success tick.

Layouts drawn by Claude for Usman to choose between. Each is shown part way through: update A has loaded, update B is still loading.

Leads with
The two files as equals. Each slot owns its own facts, progress and warnings, so a warning is always next to the file it is about.
Does well
Matches how planners think of it: last month's file and this month's. Either slot can be filled first. The report is inside the slot, so it cannot be missed or hidden by success.
Costs
Comparing the two (is B really later than A?) means reading across two cards. A long report in one slot makes the cards uneven. Half-width reports are cramped for six kinds of warning.

The comparison. The same fact for A and B sits in one column, so a wrong pair (different project, B older than A) shows at a glance.
Does well
Answers "can I trust it" as well as "did it load". One full-width report has room for six kinds of warning and shows which file each kind came from. Already looks like the product: a table of differences.
Costs
Less obvious where to drop a file before anything is loaded; the empty state needs its own design. Warnings sit one step further from the file they belong to.

Does well
Most room for each file's report. Nothing to misread: one thing at a time. The order (earlier, then later) is fixed, so the files cannot be swapped by accident.
Costs
Three steps for a job planners do every month; it will feel slow by the second use. The two files are never seen side by side until the last step. Both files cannot be dropped at once.
